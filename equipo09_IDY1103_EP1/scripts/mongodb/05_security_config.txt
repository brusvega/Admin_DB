Script 05: Configuración de seguridad en mongod.conf
(no se ejecuta con mongosh, se aplica en el archivo de
configuración del servidor y se reinicia el servicio)
=====================================================

1) AUTENTICACIÓN Y CONTROL DE ACCESO
security:
  authorization: enabled

2) AUDITORÍA (registrar login/logout, intentos fallidos y
   acceso a colecciones sensibles)
auditLog:
  destination: file
  format: JSON
  path: /var/log/mongodb/audit.json
  filter: '{ atype: { $in: ["authenticate", "authCheck", "createCollection", "dropCollection"] } }'

3) CIFRADO EN TRÁNSITO (TLS/SSL)
net:
  tls:
    mode: requireTLS
    certificateKeyFile: /etc/ssl/mongodb.pem

   Si el entorno de laboratorio no permite configurar certificados,
   se documenta como limitación y se propone habilitarlo en el
   entorno productivo. Como control compensatorio, se restringe el
   acceso a la red local del laboratorio (bindIp).

4) POLÍTICAS DE CONTRASEÑA
   - Complejidad: se exige manualmente el patrón mayúscula+minúscula+
     número+símbolo (ver credenciales de los scripts 02).
   - Expiración: MongoDB Community no soporta expiración nativa de
     contraseñas de usuarios de base de datos; se documenta como
     limitación y se propone rotación manual cada 90 días como
     control compensatorio.
   - Bloqueo por intentos fallidos: no soportado de forma nativa en
     Community Edition; se propone como mejora futura el uso de
     MongoDB Enterprise/Atlas u objetos de proxy con fail2ban sobre
     el log de autenticación.

5) RESPALDO Y MONITOREO: ver scripts 06 y 07.
